## Decisions Made

See `key-decisions` in frontmatter. Highlights:

- **fakeDevice extended in-place** rather than via a wrapper type. Same-package method addition keeps the registration call (`api.RegisterDeviceServiceServer(srv, dev)`) unchanged from Phase 2; the new GetDeviceKeys / GetDeviceActivation methods plug in automatically.
- **ABP activation state on a package-level sidecar** (`deviceRevealState`) because the Phase 2 fakeDevice had no field for it and threading a new field through `newFakeDevice()` would have required a Phase 2 constructor signature change.
- **Template generator as a separate binary** at `internal/testsupport/cmd/gen-template` so the golden XLSX is reproducible (`go run ./internal/testsupport/cmd/gen-template OUTPUT_PATH`) without coupling it to `go generate` semantics.
- **Skeleton tests use t.Skip with Wave reference strings** instead of build tags. Wave 1+ tasks can grep `Wave 1:` to find their start points; running `go test ./internal/...` produces SKIP markers (not FAIL or missing-symbol panics), so CI green stays accurate.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 — Blocking] Split Task 1's "deps + config in one commit" requirement across Task 1 and Task 2**

- **Found during:** Task 1 (immediately after `go get github.com/xuri/excelize/v2`).
- **Issue:** `go mod tidy` strips direct deps that nothing in the tree imports. Until Task 2's `xlsx_fixtures.go` actually imports excelize, the dep flips back to indirect (or gets removed entirely) on the next `go mod tidy`, which would fail Task 1's acceptance grep `grep -q "github.com/xuri/excelize/v2 v2\\.10" go.mod`.
- **Fix:** Committed Task 1 with just the web/playwright artifacts. The excelize+sync upgrade-to-direct landed naturally in Task 2's commit alongside the importing fixture code. The plan's intent ("excelize is in go.mod") is satisfied — just spread across two commits instead of one.
- **Files modified:** none additional vs. plan
- **Verification:** all final grep acceptance criteria pass; `git log` shows the dep arrives by `c1e1723` (Task 2)
- **Committed in:** `8b2f644` (Task 1) + `c1e1723` (Task 2)

**2. [Rule 2 — Missing Critical] Added a README in `web/playwright/fixtures/` documenting stub regeneration**

- **Found during:** Task 2 (creating session-state JSON).
- **Issue:** The stub JSON files have no inherent signal that they are not real session cookies. A future contributor could mistakenly believe the committed cookie value is a working session, or worse, a leaked production session — and CI failures from "stub cookie rejected by login flow" would be confusing.
- **Fix:** Wrote `web/playwright/fixtures/README.md` with the regeneration command and an explicit "these are intentionally stubs" + T-3-02 threat-model reference.
- **Files modified:** `web/playwright/fixtures/README.md` (added)
- **Verification:** README renders on GitHub; matches the threat-model note in 03-01-PLAN.md
- **Committed in:** `c1e1723` (Task 2)
