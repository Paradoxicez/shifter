# Phase 3 — UI Design Contract

> Visual and interaction contract for the **Provisioning (Gateways, Devices, Bulk Import)** phase of Shifter. Generated by `gsd-ui-researcher`, verified by `gsd-ui-checker`.
>
> **This phase inherits the Phase 1 trunk UI-SPEC wholesale and the Phase 2 extensions wholesale.** Every token (spacing, typography, color, dialog anatomy, form anatomy, state conventions, iconography, copywriting voice, ResponsiveDialog + Stepper + status-row + canonical verb table) is locked upstream and is **NOT re-specified here**. This document declares **only Phase 3 extensions and additions** — new routes (`/gateways`, `/gateways/:id`, `/admin/imports`, `/admin/imports/:job_id`, `/devices/import`), new dialog instances (Add/Edit Gateway, Decommission Gateway with warning, Bulk Import 3-step, Reveal Keys), the extended `/devices` filter/sort/pagination surface, and the 5-step Add-Device dialog (OTAA + ABP) that supersedes Phase 2's 4-step version.
>
> Any conflict with the trunk or Phase 2 contract is a defect; resolve by amending this document and noting the deviation at the top.

## Spacing Scale

**Inherited from Phase 1 trunk + Phase 2 extensions.** Tailwind 4 native scale, multiples of 4. Compact density. Form field vertical rhythm 16px, table row height 36px, button height 36px default. Touch-target exception 44px on `<md` viewports.

### Phase 3 additions

| Surface | Spacing rule | Token |
|---------|--------------|-------|
| Gateway sparkline cell | Cell fixed width `w-32` (128px), height matches table row (`h-9`, 36px), 2px vertical padding inside cell | `xs` |
| Filter toolbar (`/devices`) row | `flex flex-wrap items-center gap-3` — 12px gaps between filter controls; wraps to second line on `<md` | non-standard 12px (3 × 4) — allowed (multiple of 4) |
| Bulk-action bar (when ≥1 row selected) | Sticky strip below toolbar, `h-12` (48px), `bg-secondary border-y`, `px-4`, contains "N selected" + Decommission button + Export selected button + "Clear selection" ghost link | `2xl` (height = 48) |
| Bulk Import preview summary banner | `<Alert>` block above the per-row table — `px-4 py-3`, `gap-3` between counts and icons | `md` |
| Bulk Import per-row table | Standard TanStack Table padding (Phase 2 rules) — `py-2` cell, `border-b` row separator | `sm` |
| Bulk Import expandable reason row | Expanded panel inset `pl-12` (matches caret + checkbox column), `py-3 px-4`, `bg-muted/40` | `xl` for inset + `md` padding |
| Decommission Gateway warning banner inside `<AlertDialog>` | Inline `<Alert variant="warning">` body — `mt-3` above the description text, `px-4 py-3` | `md` |
| Reveal Keys dialog body | `gap-4` between key rows; each key row `flex items-center justify-between gap-3` | `md` |
| Gateway list 24h stats column (RX/TX + success%) | Three numeric stat groups stacked vertically with `gap-0.5` (2px) — only place 2px gap is used; multiple of 4 still satisfied via `space-y-0.5` Tailwind class which equals 2px; **explicit exception** | 2px (justified — tight numeric stat block) |
| Add Device dialog success state (keys panel) | `<Card>` with `p-6`, `gap-4` between rows, each key row `gap-2` between label and copy button | `md` / `sm` |

**Magic-number prohibition still applies.** No inline `style={{ padding: ... }}`. Sparkline width MUST be `w-32`, not `style={{ width: 128 }}`.

Semantic palette `--success` / `--warning` / `--info` / `--destructive` already exists and is enforced.

### Accent reserved for (Phase 3 extension to the trunk + Phase 2 list — exhaustive)

The trunk + Phase 2 lists still apply. Phase 3 ADDS only these accent uses:

15. The `Add device` primary button on the extended `/devices` page (no change from Phase 2 — listed for completeness).

**Forbidden accent uses (Phase 3-specific reinforcement):**

- Sparkline lines/fills: use `--muted-foreground` for the line stroke and `--primary/10` for the area-fill **only if the gateway is healthy**; degrade to `--warning/15` if uplink success % is 70–94%, `--destructive/15` if <70%. Never solid `--primary` fill (would compete with the primary CTA).
- Bulk-action sticky bar: surface is `--secondary` with `--border` top/bottom; the Decommission button inside uses `variant="destructive"`, the Export button uses `variant="outline"` — NEVER `variant="default"` on the bulk bar (the bar is contextual, not primary).
- Filter pills on `/devices`: each pill is `<Badge variant="secondary">` with a trailing `X` close icon. Never `bg-primary`.
- Outcome chips on bulk-import preview / job detail: use semantic tokens per state (see Status Encoding below). Never `--primary`.

### Status encoding (Phase 3 extension to Phase 2 table)

All status pills, dots, and badges continue to use the inherited semantic palette. Phase 3 introduces these specific mappings:

| State | Token | Where used |
|-------|-------|------------|
| Gateway online (uplink within last hour AND success % ≥ 95%) | `--success` | Gateway list status dot, gateway detail header status row |
| Gateway degraded (uplink within 24h, success % 70–94%) | `--warning` | Gateway list status dot, sparkline area fill |
| Gateway offline (no uplink in 24h, OR success % < 70%) | `--destructive` | Gateway list status dot, sparkline area fill |
| Gateway archived | `--muted-foreground` (hollow dot) | Archived rows when "Show archived" toggle ON |
| Device activation = active | `--success` | Activation filter pill, device detail activation row |
| Device activation = inactive (joined ever, no recent uplink) | `--warning` | Same as above |
| Device activation = never_joined | `--muted-foreground` | Same as above |
| Bulk import outcome = created | `--success` | Outcome chip in preview table + job detail table |
| Bulk import outcome = already_exists (idempotent skip) | `--info` | Same — **NOT** warning; idempotency is expected behavior, not a problem |
| Bulk import outcome = skipped (validation rejected, will not commit) | `--warning` | Same |
| Bulk import outcome = error (committed phase failed for this row) | `--destructive` | Job detail table only (preview phase has no "error" since it doesn't commit) |
| Reveal Keys — admin sees button | `--primary` | Button text only — the underlying gate is server-side per D-26 |
| Reveal Keys — viewer cannot see button | (button not rendered) | UI hides the entire control for non-admins |

**No new color tokens.** If a surface needs a state not listed above, the planner amends this table — it does NOT introduce a new CSS variable.

### Brand-color literal prohibition (reinforced)

Sparkline component MUST consume `var(--success)` / `var(--warning)` / `var(--destructive)` via the shadcn-chart token system. Never hardcoded `#16A34A` etc. Recharts `<Area fill={...}>` accepts CSS variables — use them.

## Layout: New Page Shells

All Phase 3 pages render inside the inherited app shell (sidebar + topbar + main content). Phase 3 inserts **two new sidebar nav items**:

```
Sidebar (Phase 3 final order):
  Gateways        ← new (Phase 3)
  Sites           ← Phase 2
  Devices         ← Phase 2 (extended in Phase 3)
  Profiles        ← Phase 2
  Settings        ← Phase 1
```

Gateways sits at the top because in operator mental model the gateway is the network edge — without it, no devices uplink. The order matches "fleet-down" causation. The `/admin/imports` route is reached via a link in the Bulk Import dialog success toast and a "Recent imports" link inside the `/devices/import` dialog footer — it is NOT a sidebar item (it's an audit-style surface that Phase 6/9 will fold into the general audit UI).

Per D-30 + D-31, soft-delete + ChirpStack DeleteGateway. Per D-31, surface a warning **inside the body** when 24h uplink count from devices behind this gateway ≥ 1.

| Element | Pattern |
|---------|---------|
| Title | "Decommission this gateway?" |
| Description (always present) | "We'll archive {gateway name} and remove it from ChirpStack. Historical telemetry from devices behind it stays preserved. You can restore later." |
| Warning banner (conditional — only if 24h uplinks ≥ 1) | Inline `<Alert variant="warning">` between description and footer: "This gateway received uplinks from **{X}** devices in the last 24 hours. | Cancel | "Cancel" (left, ghost). |
| Confirm | "Decommission gateway" — `variant="destructive"`. |

| Submit (loading) | "Decommissioning gateway…" |
| Success toast | "Gateway {name} decommissioned." |
| Failure | Inline `<Alert variant="destructive">` at top of body "ChirpStack rejected the delete: {reason}. Nothing changed." (per D-30 atomicity — Postgres archive only commits if CS DeleteGateway succeeds or its rollback succeeds.) |

## Locale & Text Handling

The Phase 1 trunk locks English-only UI. Phase 3 reaffirms this for static UI strings: **all UI text in the codebase is English literal strings**.

**However:** Phase 3 specifically handles **operator-supplied content** that may be Thai or other non-ASCII text:

| Surface | Locale handling |
|---------|-----------------|
| Site name (entered by operator in Phase 2 dialog) | Renders verbatim in `/devices` site column. Column width is `min-w-32` to fit ~12 Thai characters at 14px. |
| Device name | Verbatim. Phase 2 column already font is Inter Variable which has Thai glyph coverage (subset Latin-Ext + Thai). |
| Bulk Import file content | XLSX is preferred BECAUSE Thai operators reported Excel-on-Windows saving CSV as TIS-620/CP874 — XLSX sidesteps encoding negotiation. CSV must be UTF-8 with BOM (the Step 1 hint banner says so). |
| Bulk Import template XLSX | Header row is English (matches API field names). Example rows use English placeholder names. Operators can fill in Thai (or any UTF-8) freely. |
| Tags | Free-text UTF-8; renders in `<Badge>` chips with `truncate max-w-24` to prevent layout break. |
| Gateway description / device description | Free-text UTF-8; renders with `whitespace-pre-wrap break-words` so Thai (which has no word boundaries) wraps reasonably. |

**Font coverage:** Inter Variable (Phase 1 trunk) includes Thai glyphs via the Inter v4 family. JetBrains Mono is Latin-only — never used for operator-supplied content (only for codes/hex). If a site name or device name contains Thai, it renders in Inter, not JetBrains Mono.

**Column widths:** TanStack Table columns in `/devices` and `/gateways` use `min-w-*` (not fixed widths) for the Name column so long Thai or English names don't truncate mid-character. The Site column uses `truncate max-w-48` with full text on hover via `<Tooltip>`.

**Date/number formatting:** Inherited from Phase 1 trunk — `toLocaleString(navigator.language)` for timestamps in tables (renders as "11/05/2026 14:32" or "May 11, 2026, 2:32 PM" depending on browser locale). The install timezone (set in Phase 1 wizard) is appended for clarity on timestamps that cross day boundaries. Big numbers (RX/TX counts) render with thousands separator via `toLocaleString()`.
