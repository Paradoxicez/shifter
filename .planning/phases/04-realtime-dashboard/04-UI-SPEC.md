# Phase 4 — UI Design Contract

> Visual and interaction contract for the realtime + dashboard phase of Shifter. Generated by `gsd-ui-researcher`, verified by `gsd-ui-checker`.
>
> **This phase inherits Phase 1's trunk UI-SPEC wholesale** and extends Phase 2/3's status-encoding, TanStack Table, and sparkline patterns. Tokens (spacing, typography, color, dialog/form anatomy, state conventions, iconography, copywriting voice) are locked upstream and NOT re-specified here. This document declares **only Phase 4 extensions** — the dashboard shell, KPI tile design, chart presets, SSE-state surfaces, per-meter detail tabs, the Uplinks log table, sparkline visual rules, and the progressive-onboarding empty state.
>
> **Phase 4 introduces NO new mutations.** Every CTA that leads to a state change links to an existing Phase 3 dialog. Viewer authz: full read access on every Phase 4 surface (D-23).
>
> Any conflict with upstream trunk contracts is a defect; resolve by amending this document and noting the deviation at the top.

Phase 4-specific spacing rules (within the trunk scale — all values are multiples of 4):

| Element | Spacing | Tailwind | Rationale |
|---------|---------|----------|-----------|
| KPI tile grid (desktop ≥ md) | 24px gap between tiles | `gap-6` | Dashboard cards breathe more than form fields; matches dialog body padding |
| KPI tile grid (mobile <md) | 16px gap | `gap-4` | Tighter on small viewports |
| KPI tile internal padding | 24px (`p-6`) | `p-6` | Standard shadcn card body; matches Phase 1 dialog body |
| Dashboard chart card padding | 24px header + 16px body bottom | `p-6 pb-4` | Header has padding-bottom 0 to let chart breathe to card edges |

| MP detail tabs strip padding | 0 horizontal, 8px bottom from tabs to content | `mb-2` (under `<TabsList>`) | shadcn `<Tabs>` default; do not deviate |
| MP detail Normal tab section gap | 24px | `space-y-6` | Status row → cumulative card → instant card → sparkline triplet → quality badge row |
| MP detail sparkline triplet | 16px gap between 3 sparklines on desktop, stacked with 12px gap on mobile | `gap-4 md:gap-4` / `space-y-3 md:space-y-0` | Three sparklines fit horizontally on desktop in a single card |
| Uplinks log table cell padding | `py-2 px-3` | inherits Phase 2 TanStack Table padding | Compact density (Phase 1) |
| Uplinks log expanded row inset | `pl-12 py-3 px-4 bg-muted/40` | inherits Phase 3 D-04 bulk-import expanded-row pattern | Matches caret + first-column offset |
| JSON tree node indent (Advanced tab) | 16px per nest level | `pl-4` per `<details>` | Visually readable but not wasteful on mobile |
| Live-banner height | 36px (`h-9`) at `<md`, 32px (`h-8`) at `md+` | `h-9 md:h-8` | Above the dashboard, matches Phase 1 button heights |
| Empty-state onboarding card padding | 48px vertical, 32px horizontal on desktop; 32px / 24px mobile | `py-12 px-8 md:py-12 md:px-8` then `py-8 px-6` mobile | Phase 1 empty-state pattern |

## Color

**Inherited from Phase 1 trunk — see `01-foundation/01-UI-SPEC.md` §Color.** Phase 4 introduces NO new color tokens.

Phase 4-specific color usage rules within the trunk palette:

### KPI tile color contract

- **Tile surface:** `bg-card` with `border` (`--border`). 30% surface bucket. Never tinted blue.
- **Metric value (the number):** `text-foreground`. Never colored. The number's job is to be read accurately, not to encode state.
- **Unit:** `text-muted-foreground`.
- **Period delta arrow + percent:**
  - **Water "+" delta** (more water used than yesterday): `text-warning` + `<TrendingUp>` icon. _Water consumption increases are operator-relevant — they may indicate a leak. Coloring "up" as warning, not destructive, is intentional: it's a heads-up, not a fault._
  - **Water "−" delta** (less water than yesterday): `text-muted-foreground` + `<TrendingDown>` icon. Neutral.
  - **Electricity "+" delta**: `text-muted-foreground` + `<TrendingUp>` icon. Neutral — electricity goes up during business hours; not inherently a problem.
  - **Electricity "−" delta**: `text-muted-foreground` + `<TrendingDown>` icon. Neutral.
  - **0 delta (no change)**: `text-muted-foreground` + `<Minus>` icon.
  - **No comparison available** (install younger than 24h): `text-muted-foreground` text "—" with tooltip "Comparison available after 24 hours of history."
  - _Rationale:_ semantic color belongs to actionable signal. Phase 6 alerts use destructive for true threshold breaches; Phase 4 dashboard limits itself to one operator-attention nudge (water-up = warning), nothing else. Anomaly detection lives in Phase 6/7.
- **Online / offline count tile:**
  - All online: count in `text-foreground` + label "12 of 12 online" with `<CheckCircle2 className="text-success">` 16px leading icon.
  - Some offline: count in `text-foreground` + label "10 of 12 online" with `<AlertCircle className="text-warning">` icon.
  - All offline: count in `text-foreground` + label "0 of 12 online" with `<XCircle className="text-destructive">` icon.
  - _Color is on the leading icon only — count itself stays foreground for legibility._

### Chart color contract (Recharts via `chart.tsx`)

- **Cumulative-value line stroke:** `var(--primary)` (navy). Single series per chart; one chart per utility class. Primary is the accent — using it here is the "10%" budget for the dashboard hero charts. _Reserved use #8 (extending Phase 1 §Accent reserved for): "Dashboard cumulative chart line stroke (one chart per utility class)."_ Amend the Phase 1 trunk accent list with this addition.
- **Cumulative-value area fill:** `var(--primary)` at `/10` alpha (`bg-primary/10` equivalent via Recharts `fillOpacity={0.1}`). Subtle, non-competitive.
- **Chart axis ticks / grid lines:** `var(--border)`. Never tinted.
- **Chart axis label text:** `var(--muted-foreground)`, `text-xs`.
- **Chart tooltip (Recharts default):** `bg-popover text-popover-foreground border` via shadcn `<ChartTooltip>` already exported by `chart.tsx`.
- **No multi-color series.** If multiple MPs are summed into a single line, the operator reads "the total" — not per-MP breakdown. Per-MP breakdown lives on the MP detail page (one MP = one line = still primary).
- **Live-mode last-bucket marker:** subtle pulsing dot (4px) at the rightmost data point in `var(--primary)` with `animate-pulse` when range = Today or 24h. Disabled at `prefers-reduced-motion`. Other presets: no marker.

### Sparkline color contract (per-meter Battery / RSSI / SNR — last 24h hourly buckets)

Inherits Phase 3 sparkline pattern but applied to per-meter health metrics rather than per-gateway RX/TX. Three sparklines side-by-side in one Normal-tab card:

| Metric | Healthy band | Warning band | Critical band | Stroke + fill colors |
|--------|--------------|--------------|---------------|----------------------|
| **Battery (V or %)** | Above profile-declared low threshold (or > 30% if no threshold) | 10–30% (or just-above-low if threshold declared) | < 10% (or below-low if threshold declared) | Stroke `var(--muted-foreground)` always; fill `var(--success)/10` healthy, `var(--warning)/15` warning, `var(--destructive)/15` critical |
| **RSSI (dBm, negative = farther)** | > −105 dBm | −115 to −105 dBm | < −115 dBm | Same stroke + fill semantic as Battery |
| **SNR (dB)** | > 0 dB | −10 to 0 dB | < −10 dB | Same stroke + fill semantic as Battery |

- Stroke is always `var(--muted-foreground)` — sparkline lines themselves are neutral so they don't compete with the dashboard chart's primary line.
- Fill encodes the **current value's** state (not a trend), exactly per Phase 3 D-02 / 03-UI-SPEC §Color §Sparkline lines/fills rule. Reaffirmed here for the per-meter case.
- Sparkline width: `w-full` inside its card column. Height: `h-16` (64px) — small enough that three fit vertically on mobile, tall enough to read trend on desktop.
- _No solid `var(--primary)` fill anywhere on these sparklines._ Primary is reserved for the dashboard chart.

### Advanced-tab JSON tree primitive value colors

The Advanced tab is the only Phase 4 surface where typed primitives benefit from color encoding. Operator scans nested vendor JSON and needs to distinguish "number 0" from "boolean false" at a glance.

| Type | Color | Example |
|------|-------|---------|
| `string` | `text-success` | `"unit": "m³"` → "m³" in success |
| `number` (integer or float) | `text-info` | `"cumulative": 12.45` → "12.45" in info |
| `boolean` | `text-warning` | `"alarm": true` → "true" in warning |
| `null` | `text-muted-foreground italic` | `"reset_at": null` → "null" italic muted |
| _key_ (always) | `text-foreground font-semibold` (mono) | unchanged from typography spec |

- Color encodes _type_, not _value_. A boolean `false` is the same color as `true` — both are warning so the operator sees flags consistently.
- This is the **only** Phase 4 use of semantic colors for non-state encoding. It's allowed because Advanced is a developer-style surface — the rules of "color = state" relax inside a JSON inspector where type-color is the universal convention (and matches Chrome DevTools' palette by happy coincidence). _Not a new rule for other phases — Phase 7 codec test-runner inherits this and nothing else does._

### Live-channel banner color contract

- Disconnected (during reconnect, no snapshot yet replayed): `<Alert variant="warning">` with `<RotateCw className="animate-spin">` icon. Copy: "Reconnecting to live updates…" + sublabel "Last snapshot 12 sec ago" (mono).
- Disconnected for > 30 seconds: same surface, copy escalates to "Live updates paused" + sublabel "Showing last-known values from {time}." Color stays warning (not destructive — the data on screen is still valid persisted data).
- Reconnected + fresh snapshot received: banner dismisses (no toast — the dashboard updating is its own confirmation, and toasts shouldn't fire on background events).
- _No "connected" green banner._ The default state is connected; the dashboard updating is the indicator. Showing a "connected" banner is noise.

### 60/30/10 enforcement (Phase 4 audit)

- **60% dominant (`--background`)**: dashboard page background, MP detail page background, KPI grid background, empty-state outer background. Never tinted.
- **30% surface (`--card`)**: every KPI tile, chart card, MP detail tab content card, Uplinks log table container, sparkline triplet card, onboarding empty-state card.
- **10% accent (`--primary`)**: dashboard cumulative chart line (extends Phase 1 accent list — see Chart color contract above); active sidebar Dashboard item (Phase 1 trunk); active tab (`<TabsTrigger>` shadcn default underlines with primary); date-range preset active button background (uses `data-state="active":bg-secondary` on the chip, but the underline marker uses primary). Quality-badge accent text on hover remains `--warning`, not primary.

### Accent additions to Phase 1's reserved list

Phase 1's accent list (1–7) is extended in Phase 4 with:

8. **Dashboard cumulative chart line + area fill (per utility class, one chart each).** `--primary` stroke and `--primary/10` area only.
9. **Live-mode last-bucket pulse marker** on Today / 24h dashboard charts only. `--primary` with `animate-pulse`.
10. **MP detail tab active indicator underline** (shadcn `<TabsTrigger>` default — explicitly affirmed, not a new use).

No other accent use. Sparklines, KPI metric values, Advanced-tab JSON, Uplinks log table, status rows: all use semantic / muted / foreground tokens.

#### Adaptive layout per scope (D-09)

| Scope | KPI tile count | Chart cards |
|-------|----------------|-------------|
| `water` | 4 tiles (Today / Current flow / Period delta / Online) — all water-scoped | 1 chart card (water cumulative) |
| `electricity` | 4 tiles — all electricity-scoped (Today's kWh / Current draw W / Period delta / Online) | 1 chart card (electricity cumulative) |
| `both` | 8 tiles in a 4×2 grid (4 water + 4 electricity, water first; on mobile they stack 4-wide responsive) | 2 chart cards stacked (water first, electricity below) |

**Order rule:** Water always renders before electricity (alphabetical + matches the broader water-monitoring focus of typical Shifter customers). The order is fixed — not user-configurable in Phase 4.

#### Responsive behavior

| Breakpoint | KPI grid | Chart card |
|-----------|----------|-----------|
| `<sm` (mobile <640px) | 1 column (4 tiles stacked per utility) | full-width, height `h-48` |
| `sm` to `md` (640–767px) | 2 columns | full-width, height `h-56` |
| `md` to `lg` (768–1023px) | 4 columns (single row for one scope; two rows for `both`) | full-width, height `h-64` |
| `lg+` (≥1024px) | 4 columns | full-width, height `h-72` |

Chart container uses `<ChartContainer>` from `chart.tsx` which delegates to Recharts `<ResponsiveContainer>` — width auto-fills, height is set via Tailwind class on the container wrapper.

#### Date-range preset picker

Top-right of page header. Single segmented control:

```
[ Today ] [ 24h ] [ 7d ] [ 30d ] [ Custom ▼ ]
```

- Buttons: `<Button variant="ghost" size="sm">` with `data-state="active":bg-secondary` styling. Active button shows `text-foreground font-semibold`; inactive shows `text-muted-foreground font-semibold`.
- Custom: `<Popover>` opens shadcn `<Calendar mode="range">` with a 2-month side-by-side calendar on desktop, single-month on mobile. Selecting a range commits on second click + closes the popover.
- URL state: `?range=today|24h|7d|30d|custom&start=...&end=...` (ISO timestamps for custom). Back/forward navigates between ranges. Sharing the URL preserves the view. Pattern mirrors Phase 3 D-15.

### Voice notes for Phase 4

- **Numbers are facts, not boasts.** "47.2 m³" not "An impressive 47.2 m³". Numbers carry their own weight.
- **Live language is calm.** "Reconnecting to live updates…" not "Connection lost!" or "ERROR: SSE FAILED". The operator already saw the dashboard freeze; the banner is reassurance, not alarm.
- **Empty-state copy explains cause.** "Without one, devices can't reach Shifter" — the WHY makes the CTA feel mandatory, not arbitrary.
- **Time is contextual.** "12 sec ago" (mono) for recent; "Last update at 14:32:08" (mono) for older same-day; ISO for cross-day on hover only. _Operators don't need precision to the millisecond on a live dashboard — they need fast scanning._

## Accessibility (Phase 4 audit)

Inherits Phase 1 trunk rules. Phase 4-specific extensions:

- **Live region for SSE updates:** the dashboard KPI tile container has `aria-live="polite"` so SSE-driven value changes are announced by screen readers (without interrupting the user). Charts use `role="img"` with an `aria-label` summarizing the latest value + trend ("Water cumulative chart, last 24 hours, current 1234.56 m³, up 8% from yesterday").
- **Live-channel banner:** `role="status"` `aria-live="polite"` for reconnecting state; `role="alert"` `aria-live="assertive"` for auth-expired state (sign-in-required is urgent).
- **Tabs:** shadcn `<Tabs>` is keyboard-accessible by default (arrow keys, Home, End). Phase 4 affirms this — no overrides.
- **Quality badge:** must be a `<button>` (not just a styled `<Badge>` div) since it's interactive. `aria-label="View {N} flagged uplinks of the last 100"`.
- **JSON tree:** each expandable node is a `<button>` with `aria-expanded="true|false"`. Focus order is depth-first (top-down). Arrow keys move sibling-to-sibling within the same nest level.
- **Date-range preset picker:** `role="radiogroup"` with each button as `role="radio"` and `aria-checked="true|false"`. Arrow keys navigate. The "Custom" trigger inside is a separate `<button>` with `aria-haspopup="dialog"`.
- **Sparklines:** each sparkline has an `aria-label` summarizing trend ("Battery sparkline, last 24 hours, current 3.6 V, decreasing trend"). _Per WCAG, decorative-looking charts still need a text alternative._
- **Color is never alone:** every status uses dot + label + (where applicable) icon. The KPI period-delta color is reinforced by `<TrendingUp>` / `<TrendingDown>` / `<Minus>` icon. The online/offline tile uses the count + the label suffix ("12 of 12 online") in addition to the leading icon color.
- **Focus order on dashboard:** Date-range picker → KPI tile 1..N (in DOM order) → chart card 1..M (chart is non-focusable; the card-level "Retry" link if present is focusable) → bottom of page.
- **Focus order on MP detail:** Page heading (`<h1>` focused on route entry) → Tabs strip → active tab content's interactive elements → bottom of page.
- **Reduced motion (`prefers-reduced-motion`):** disables `animate-spin`, `animate-pulse`, the live-mode chart pulse marker, the Uplinks log new-row prepend pulse, and the empty-state Step 3 loader (becomes static). Chart and sparkline rendering itself is unaffected (Recharts SVG has no animation by default in `chart.tsx`).
- **Mobile touch targets (Phase 1 trunk):** date-range preset buttons reach 44px height on `<md`; tab triggers reach 44px height on `<md`; quality badge reaches 44px tappable area on `<md` (button itself stays small, but `<button>` wrapping padding extends the hit area).
