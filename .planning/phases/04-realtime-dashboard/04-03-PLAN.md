**SSE wire format (verbatim — match exactly):**

```
HTTP/1.1 200 OK
Content-Type: text/event-stream
Cache-Control: no-cache
Connection: keep-alive
X-Accel-Buffering: no

event: snapshot
data: {"ready":true,"topics":["dashboard:global","mp:abc-123"]}

: heartbeat

event: measurement
data: {"metering_point_id":"abc-123","time":"2026-05-11T12:34:56.789Z","cumulative_value":1234.56,"instant_value":4.2,"quality":"ok","battery_pct":87,"rssi":-65}

: heartbeat
```

Each frame ends with `\n\n`. Heartbeat is a comment line `: heartbeat\n\n` every 30s. SSE comments are ignored by the EventSource API but keep the TCP connection alive.

**Topic source on connect:** read `?topics=dashboard:global,mp:abc-123` from query string. Up to 64 topics per connection (planner cap; reject 400 if exceeded). Validate each topic matches `^(dashboard:global|mp:[0-9a-f-]{36}(:uplinks)?)$`.

**Topic-set changes after connect:** the client reconnects with a new `?topics=...` query string. There is no subscribe/unsubscribe HTTP API in Phase 4. The frontend `useSSE` hook (Plan 06) already implements this reconnect-instead-of-update approach (D-04 reconnect-and-snapshot semantics — every reconnect emits a fresh snapshot, so cache invalidation is uniform).

**D-23 authz:** route mounts under the authenticated group (SessionMgr.LoadAndSave + auth required) but does NOT require admin. Viewers get full SSE access.

**Caddy SSE matcher (production):** the existing `Caddyfile` `@sse` matcher only matches `path /sse /sse/*`. <design_notes>
**v1 server-side capability filter — intentionally deferred (Flag 2 acknowledgement).**

Phase 4 emits all measurement events on `dashboard:global` regardless of `install_identity.capabilities` (D-09). KPI rendering is client-filtered: the dashboard only renders panels matching the configured capability, so the operator never sees off-scope numbers. This is a v1 tradeoff:

- Single-tenant install + small fleet (≤ a few hundred MPs at peak) means the bandwidth cost of emitting both utility classes is negligible.
- An install with `capabilities=both` already needs every event; an install with `capabilities=water` or `electricity` simply drops the off-class deltas in the client.
- Server-side fan-out filtering by capability is tracked as a Phase 6 follow-up (REQUIREMENTS §Phase 6 candidates).

If a future install with both utilities later chooses to display only one and wants to save the bandwidth, that's the trigger to lift the filter into Hub.

**Subscribe/unsubscribe endpoints — deferred (Flag 3 / option b).**

Earlier drafts contemplated `POST /api/events/subscribe` and `DELETE /api/events/subscribe` to mutate an open stream's topic set. Phase 4 ships WITHOUT these endpoints:

- Plan 06's `useSSE` already chose reconnect-instead-of-update (every topic-set change closes the EventSource and reopens with a fresh `?topics=...` query string).
- D-04 reconnect semantics already emit a full snapshot on every reconnect, so the React-Query cache invalidation path is uniform whether the reconnect is from network loss or topic change.
- Two fewer handlers, no `conn_id` round-tripping, no auth-owner-matches-conn-id check needed.

If a future phase needs to mutate topics without dropping the EventSource (e.g., very large topic sets where reconnect cost matters), revive the endpoints then. Tracked as a non-blocking future enhancement.
</design_notes>

```go
package events

import (
    "context"
    "encoding/json"
    "errors"
    "fmt"
    "net/http"
    "regexp"
    "strings"
    "time"

    "github.com/google/uuid"
)

const (
    maxTopicsPerConnection = 64
    heartbeatInterval      = 30 * time.Second
)

var topicRegex = regexp.MustCompile(`^(dashboard:global|mp:[0-9a-f-]{36}(:uplinks)?)$`)

type Deps struct {
    Hub    *Hub
    Logger *slog.Logger
}

func (d Deps) handleSSE(w http.ResponseWriter, r *http.Request) {
    topics, err := parseTopics(r.URL.Query().Get("topics"))
    if err != nil {
        http.Error(w, err.Error(), http.StatusBadRequest)
        return
    }

    flusher, ok := w.(http.Flusher)
    if !ok {
        http.Error(w, "streaming unsupported", http.StatusInternalServerError)
        return
    }

    w.Header().Set("Content-Type", "text/event-stream")
    w.Header().Set("Cache-Control", "no-cache")
    w.Header().Set("Connection", "keep-alive")
    w.Header().Set("X-Accel-Buffering", "no")
    w.WriteHeader(http.StatusOK)

    connID := uuid.NewString() // internal correlation only — NOT emitted on the wire
    ch := d.Hub.Subscribe(connID, topics)
    defer d.Hub.Unsubscribe(connID)

    // Snapshot-ready marker per D-03. The actual snapshot payload is fetched
    // by the client from REST endpoints (Plan 04 dashboard/snapshot, Plan 05
    // metering-points/:id/detail). The marker tells the client "you're live;
    // go fetch your snapshot now." Wire shape: {"ready": bool, "topics": []string}.
    snapshotMsg, _ := json.Marshal(map[string]any{"ready": true, "topics": topics})
    fmt.Fprintf(w, "event: snapshot\ndata: %s\n\n", snapshotMsg)
    flusher.Flush()

    heartbeat := time.NewTicker(heartbeatInterval)
    defer heartbeat.Stop()

    for {
        select {
        case <-r.Context().Done():
            return
        case payload, open := <-ch:
            if !open {
                return
            }
            fmt.Fprintf(w, "event: measurement\ndata: %s\n\n", payload)
            flusher.Flush()
        case <-heartbeat.C:
            fmt.Fprint(w, ": heartbeat\n\n")
            flusher.Flush()
        }
    }
}

func parseTopics(raw string) ([]string, error) {
    if raw == "" {
        return nil, errors.New("topics query param required")
    }
    parts := strings.Split(raw, ",")
    if len(parts) > maxTopicsPerConnection {
        return nil, fmt.Errorf("too many topics (max %d)", maxTopicsPerConnection)
    }
    for _, t := range parts {
        if !topicRegex.MatchString(t) {
            return nil, fmt.Errorf("invalid topic: %q", t)
        }
    }
    return parts, nil
}
```
