**Mirror this shape (verified from internal/resolver/listener.go):**

```go
const reconnectBackoff = 2 * time.Second

func (h *Hub) Run(ctx context.Context, pool *pgxpool.Pool, log *slog.Logger) {
    for {
        if ctx.Err() != nil { return }
        err := h.runOnce(ctx, pool, log)
        if ctx.Err() != nil { return }
        log.Warn("events listener disconnected, reconnecting", "err", err)
        select {
        case <-ctx.Done(): return
        case <-time.After(reconnectBackoff):
        }
    }
}

func (h *Hub) runOnce(ctx context.Context, pool *pgxpool.Pool, log *slog.Logger) error {
    conn, err := pool.Acquire(ctx)
    if err != nil { return fmt.Errorf("acquire: %w", err) }
    defer conn.Release()
    if _, err := conn.Exec(ctx, "LISTEN measurement_inserted"); err != nil {
        return fmt.Errorf("LISTEN: %w", err)
    }
    for {
        notif, err := conn.Conn().WaitForNotification(ctx)
        if err != nil { return fmt.Errorf("WaitForNotification: %w", err) }
        h.dispatch(notif.Payload)
    }
}
```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Postgres notification queue → Go process | NOTIFY payloads are trusted (we wrote the trigger), but malformed JSON must not crash the listener |
| Hub.Broadcast → SSE writer goroutine | Slow consumer must not block the listener (single point of fan-out for the whole process) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-02-01 | Denial of service | listener goroutine blocks on slow subscriber | mitigate | Hub.Broadcast uses non-blocking `select { case ch <- payload: default: drop+log }` per PITFALL §9. CONTEXT marks the drop-oldest vs disconnect policy as Claude's Discretion — choose drop-oldest + emit a "force re-snapshot" hint on next event. |
| T-04-02-02 | Denial of service | bad JSON crashes decoder | mitigate | `json.Unmarshal` errors are logged at WARN and the payload is dropped; listener continues. |
| T-04-02-03 | Tampering | spoofed NOTIFY payload | accept | The NOTIFY channel is internal to the DB; only our trigger writes to it. Any compromise that lets an attacker run pg_notify is already DB-level RCE. |
</threat_model>
