    ```sql
    -- Telemetry hypertable (DATA-01, DATA-02, DATA-03, DATA-07, DATA-08).
    -- D-02 frozen canonical column set; future additions are migrations.
    -- D-03: `time` is server-side ingest (NEVER gateway_rx_time — Pitfall 4).
    -- D-06: chunk_time_interval = 1 day (TigerData IoT recommendation).
    -- D-08: hybrid wide+JSONB schema — Layer-1 typed columns + extra JSONB.
    -- D-26: quality flag — never silent-drop; persist all uplinks with reason.
    -- NO device_id column on this table — telemetry is keyed by metering_point_id
    -- only (DATA-01 + Pitfall 1). The active binding at write time implies the
    -- device; later swaps don't break historical queries.

    CREATE TABLE measurement (
        time              TIMESTAMPTZ NOT NULL,
        metering_point_id UUID NOT NULL,
        raw_value         NUMERIC,
        cumulative_value  NUMERIC,
        instant_value     NUMERIC,
        battery_pct       SMALLINT,
        rssi              SMALLINT,
        snr               REAL,
        temperature_c     REAL,
        pressure_kpa      REAL,
        leak_detected     BOOLEAN,
        tamper_detected   BOOLEAN,
        extra             JSONB NOT NULL DEFAULT '{}'::jsonb,
        raw_payload       BYTEA NOT NULL,
        decoded_object    JSONB NOT NULL,
        quality           TEXT NOT NULL DEFAULT 'ok',
        fcnt              INTEGER,
        gateway_rx_time   TIMESTAMPTZ,
        device_time       TIMESTAMPTZ,
        binding_id        UUID,
        CONSTRAINT measurement_quality_valid CHECK (
            quality IN ('ok','decode_fail','missing_canonical','out_of_range','duplicate_fcnt')
        )
    );

    -- Hypertable conversion. Function form per docs.tigerdata.com/api/latest/hypertable/create_hypertable.
    SELECT create_hypertable('measurement', 'time', chunk_time_interval => INTERVAL '1 day');

    -- Hot-path index: per-MP latest reading + history queries.
    CREATE INDEX measurement_mp_time_idx ON measurement (metering_point_id, time DESC);
    -- Vendor-specific extra-field GIN for advanced view (DETL-01 in Phase 4).
    CREATE INDEX measurement_extra_gin ON measurement USING GIN (extra jsonb_path_ops);
    -- Quality-flag filtered partial index for the "X uplinks flagged" badge (D-26).
    CREATE INDEX measurement_quality_flagged_idx ON measurement (metering_point_id, time DESC)
        WHERE quality <> 'ok';

    -- LISTEN/NOTIFY trigger for measurement is RESERVED for Phase 4 SSE — Phase 2
    -- does NOT add this trigger (emitting NOTIFY on every uplink with no subscribers
    -- is wasted work). Phase 2 only adds binding_changed (Plan 02-07).
    ```

    NOTE on `binding_id`: forward-compat. The active binding at insert time is captured (resolved by ingest pipeline) so future Phase 4/5 queries can JOIN through the historical binding without time-range gymnastics. Nullable — old rows from edge cases (no binding covers timestamp) leave it NULL with quality='missing_canonical' per D-26 + Open Q#3.

    NOTE on absence of FK constraints: hypertable child chunks don't propagate FKs cleanly across all TimescaleDB versions; the ingest pipeline validates metering_point_id exists at write time (and resolver only returns valid MPs by construction). The btree_gist EXCLUDE on `binding` already enforces the consistency we need.

    Write 0016_audit_log.up.sql with the exact 10 columns per D-22 (D-22 lists 9; add `id` UUID PK as the 10th):
    ```sql
    -- D-21: audit scope = CRUD on Site, Metering Point, Device, Device Profile,
    -- Binding + meter swap action. Auth-event auditing deferred to Phase 6.
    -- D-22: single audit_log table; 10 columns.
    -- D-23: writes are synchronous in the SAME txn as the domain mutation.
    -- D-24: before/after capture changed fields only (diff-like).
    -- D-06: regular Postgres table (NOT hypertable). Phase 6 re-evaluates if
    -- volume justifies converting; for now hundreds-of-rows-per-day per install
    -- is a regular B-tree workload.
    -- Security: rows are INSERT-ONLY. UPDATE/DELETE rejected by trigger
    -- (per RESEARCH §Security Domain "Audit log tampering" mitigation).

    CREATE TABLE audit_log (
        id           UUID PRIMARY KEY DEFAULT gen_random_uuid(),
        time         TIMESTAMPTZ NOT NULL DEFAULT now(),
        user_id      UUID NULL REFERENCES "user"(id) ON DELETE SET NULL,
        action       TEXT NOT NULL,
        entity_type  TEXT NOT NULL,
        entity_id    UUID NOT NULL,
        before       JSONB,
        after        JSONB,
        notes        TEXT,
        request_id   TEXT,
        CONSTRAINT audit_log_action_valid CHECK (action IN (
            'create','update','archive','restore','swap','decommission',
            'profile_create','profile_update','binding_open','binding_close',
            'rollover_detected'
        )),
        CONSTRAINT audit_log_entity_type_valid CHECK (entity_type IN (
            'site','metering_point','device','device_profile','binding'
        ))
    );

    CREATE INDEX audit_log_time_idx        ON audit_log (time DESC);
    CREATE INDEX audit_log_user_idx        ON audit_log (user_id, time DESC);
    CREATE INDEX audit_log_entity_idx      ON audit_log (entity_type, entity_id, time DESC);
    CREATE INDEX audit_log_request_id_idx  ON audit_log (request_id) WHERE request_id IS NOT NULL;

    -- Audit log tampering mitigation: prevent UPDATE/DELETE by anyone except
    -- a privileged maintenance role. Application MUST only INSERT.
    CREATE OR REPLACE FUNCTION audit_log_reject_modification() RETURNS trigger AS $$
    BEGIN
        RAISE EXCEPTION 'audit_log is INSERT-ONLY (rejected % on row %)', TG_OP, OLD.id;
        RETURN NULL;
    END;
    $$ LANGUAGE plpgsql;

    CREATE TRIGGER audit_log_no_update
        BEFORE UPDATE ON audit_log
        FOR EACH ROW EXECUTE FUNCTION audit_log_reject_modification();

    CREATE TRIGGER audit_log_no_delete
        BEFORE DELETE ON audit_log
        FOR EACH ROW EXECUTE FUNCTION audit_log_reject_modification();
    ```

    NOTE on user_id ON DELETE SET NULL: Phase 6 will add user mgmt with disable (no hard-delete per USER-01) but defensive: if a user IS hard-deleted (admin emergency), audit rows survive with user_id NULL rather than cascading away.

    NOTE on action vocabulary: covers every Phase 2 mutation per D-22 + adds `rollover_detected` for the DATA-05 device-health event per D-05. Plan 02-07 (audit package) MUST use these exact strings.

    NOTE on entity_type vocabulary: 5 entities per D-22.

    ```sql
    DROP INDEX IF EXISTS audit_log_request_id_idx;
    DROP INDEX IF EXISTS audit_log_entity_idx;
    DROP INDEX IF EXISTS audit_log_user_idx;
    DROP INDEX IF EXISTS audit_log_time_idx;
    ```

| Application code ↔ measurement | Ingest pipeline writes measurement rows; quality flag must always be set per D-26 |

| Replay attack ↔ measurement | ChirpStack v4 dedupes by (dev_eui, fcnt) server-side; defense-in-depth quality='duplicate_fcnt' if seen |
