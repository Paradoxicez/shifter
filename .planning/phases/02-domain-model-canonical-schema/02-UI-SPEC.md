# Phase 2 — UI Design Contract

> Visual and interaction contract for the domain-model phase of Shifter. Generated by `gsd-ui-researcher`, verified by `gsd-ui-checker`.
>
> **This phase inherits Phase 1's trunk UI-SPEC wholesale.** Every token (spacing, typography, color, dialog anatomy, form anatomy, state conventions, iconography, copywriting voice) is locked by `01-foundation/01-UI-SPEC.md` and is NOT re-specified here. This document only declares **Phase 2 extensions and additions** — new surfaces, new icons, new copy, and new patterns specific to Sites, Metering Points, Devices, Profiles, the Add-Device flow, Meter Swap, and the Audit substrate.
>
> Any conflict with Phase 1's contract is a defect; resolve by amending this document and noting the deviation at the top.

## Spacing Scale

**Inherited from Phase 1 trunk — see `01-foundation/01-UI-SPEC.md` §Spacing.**

Tailwind 4 native scale, multiples of 4. Compact density. Form field vertical rhythm 16px, table row height 36px, button height 36px default. Touch-target exception 44px on `<md` viewports.

### Phase 2 additions

| Surface | Spacing rule | Token |
|---------|--------------|-------|
| Two-pane profile editor split | `gap-6` (24px) between panes; `lg+` viewports only — collapse to stacked on `<lg` | `lg` |
| TanStack Table row vertical padding | `py-2` (8px) per cell — total row ~36px including 14px text + 8px top/bottom | `sm` |
| TanStack Table header row | `py-2` + `border-b` | `sm` |
| Capability chips inside profile rows | `gap-1` (4px) between chips, `px-2 py-0.5` chip padding | `xs` |
| Status-row component (reused from Phase 1 Test Connection) | unchanged: dot 8px + `gap-2` + label + `text-mono` detail | trunk |
| Stepped-dialog body inside step | `gap-4` between fields | `md` |

**Magic-number prohibition still applies.** Profile editor's JSON tree indentation uses `pl-{n}` (multiples of 4) — never `style={{ paddingLeft: ... }}`.

## Color

**Inherited from Phase 1 trunk — see `01-foundation/01-UI-SPEC.md` §Color.**

OKLCH tokens already shipped in `web/src/theme.css`. Light + dark mode both supported. 60/30/10 split: `--background` (60%) / `--card` (30%) / `--primary` (10% — navy `oklch(0.42 0.17 255)` light, `oklch(0.65 0.18 250)` dark). Semantic palette `--success` / `--warning` / `--info` / `--destructive` already exists.

### Accent reserved for (Phase 2 extension to trunk list — exhaustive)

The Phase 1 list still applies. Phase 2 ADDS only these accent uses:

8. The "Submit" button on the final step of the Add-Device stepped dialog ("Add device").
9. The "Confirm swap" button on the final step of the Meter-Swap stepped dialog.
10. The "Save profile" button in the profile editor toolbar (single primary CTA per surface).
11. The active row indicator in the JSON-tree leaf list when an operator clicks a leaf to bind it (a 2px left border in `--primary` plus `bg-primary/10` background).
12. The active step indicator dot in Add-Device and Meter-Swap stepped dialogs (same pattern as the wizard).

**Forbidden accent uses (Phase 2-specific):**
- TanStack Table header rows (use `--card` + `--border` divider).
- TanStack Table row hover (use `bg-secondary`, never `bg-primary/...`).
- Capability chips (each chip uses `bg-secondary text-secondary-foreground`, NOT `bg-primary`).
- Status dots on quality-flag badges (use semantic colors per state — see Status Encoding below).
- Site / MP / Device row "active" or "selected" highlight (use `bg-secondary`, never `bg-primary/10` — `bg-primary/10` is reserved for the JSON-tree leaf binding state above).

### Status encoding (Phase 2 extension)

All status pills, dots, and badges use the inherited semantic palette. Phase 2 introduces these specific mappings — they MUST be used consistently in every Phase 2 surface and inherited unchanged by Phases 3+:

| State | Token | Where used |
|-------|-------|------------|
| Healthy / online / `quality = 'ok'` | `--success` | Site row health, Device last-seen-recent, MP latest measurement OK |
| Stale / late uplink (≤ 2× expected interval) | `--warning` | Device last-seen-late row, MP "no uplink in N min" hint |
| Offline / failed / unreachable / `quality = 'decode_fail'` | `--destructive` | Device offline, profile sync failed, ChirpStack pre-flight failed in Add-Device review |
| `quality = 'missing_canonical'` (codec drift) | `--warning` | "X uplinks flagged" badge — this is operator attention, not full-stop alarm |
| Archived / decommissioned | `--muted-foreground` | Archived sites/MPs in "Archived" tab, decommissioned devices |
| Informational ("Sync queued", "ChirpStack reachable, profile up to date") | `--info` | Profile sync status row, neutral notes in stepped dialogs |

**No new color tokens.** If a surface needs a state not listed above, the planner amends this table — it does NOT introduce a new CSS variable.

### Stepped dialog: Add Device (large, `sm:max-w-2xl`)

Inherits the wizard's stepper pattern. 4 steps. Footer: `[Back ghost-left]` `[Step N of 4 center]` `[Next primary-right]` (`Add device` on step 4).

#### Step 1 — Paste DevEUI

| Element | Pattern |
|---------|---------|
| Heading | "Paste the DevEUI from the meter sticker" |
| Description | "We'll show both endianness interpretations so you can pick the right one." |
| Field | `<Input>` with `font-mono` styling, placeholder "0102030405060708". Accepts spaces / hyphens / colons — strips on blur. |
| Preview rows (after paste) | Two `<Card>`-bordered radio rows: `[ ] MSB-first: 01:02:03:04:05:06:07:08 (Vendor: Axioma)` + `[ ] LSB-first: 08:07:06:05:04:03:02:01 (Vendor: unknown)`. Operator clicks the right interpretation. |
| Vendor OUI hint | Trailing `text-xs text-muted-foreground` after each interpretation's hex string when OUI lookup matches a known vendor. |
| Validation | Both interpretations valid hex AND length = 16 chars after strip. Error: "Enter a 16-character hex DevEUI." |

#### Step 2 — Pick device profile

| Element | Pattern |
|---------|---------|
| Heading | "Choose a device profile" |
| Description | "The profile sets the codec, expected interval, and which canonical fields are populated." |

| AppKey field | `<Input>` font-mono, masked toggle via `Eye`/`EyeOff` icon button (Phase 1 trunk pattern), placeholder "32 hex chars". |
| JoinEUI field | `<Input>` font-mono, placeholder "16 hex chars" — defaults to `0000000000000000` if profile doesn't override. |
| Activation | Read-only "OTAA" with `text-xs text-muted-foreground` hint "ABP support arrives in Phase 3." (Phase 2 only ships OTAA per CONTEXT.md scope.) |
| Custom profile shortcut | Below the select, link "Need a profile not listed? Create one →" — opens `/profiles/new` in a new tab and shows a notice "Return to this dialog after saving." Step 1 state is preserved. |

#### Step 3 — Bind to metering point

| Element | Pattern |
|---------|---------|
| Heading | "Bind to a metering point" |
| Description | "Telemetry from this device will be keyed on the metering point you choose. You can swap the device later without losing history." |
| MP select | `<Combobox>` (shadcn `command` inside `popover`) listing all non-archived MPs grouped by site. Format: "{Site name} — {MP name}". Empty result shows the inline shortcut row "+ Create new metering point". |
| Inline create panel | When operator picks "+ Create new metering point", a nested form appears in the same step body (NOT a new dialog) with the 4 MP fields (name, site, utility_class, location_description). Submit creates the MP, closes the inline panel, selects the new MP. Form errors render inline. |

#### Step 4 — Review and submit

| Element | Pattern |
|---------|---------|
| Heading | "Review and add" |
| Description | "We'll create everything in ChirpStack and Shifter in one step. If anything fails, nothing is saved." |
| Summary list | Read-only rows: DevEUI (mono), Profile, AppKey (masked, last 4 chars visible), JoinEUI (mono), Metering point (with site path). Each row has an "Edit" link that jumps back to the relevant step preserving entered values. |
| ChirpStack pre-flight | Inline status-row component (Phase 1 pattern) running `gRPC` + `MQTT` reachability ping on step entry. PASS rows green; FAIL row blocks the `Add device` button and shows "ChirpStack unreachable. Settings → Test connection." with a link. |
| Submit (idle) | "Add device" — primary, full-width on mobile, default-width on desktop. |
| Submit (loading) | "Adding device…" — spinner + button stays width-stable. |
| Submit (success) | Dialog closes; toast `variant="success"` "Device {name} added and bound to {MP name}". Caller route receives the new device id and may navigate. |
| Submit (failure) | Inline `<Alert variant="destructive">` at top of body: "ChirpStack rejected the device: {reason}." — entered fields preserved, operator can correct and retry. |

## Form Conventions (Phase 2 extensions)

**Inherited from Phase 1 trunk.** All trunk rules apply (label above input, helper below, error inline below helper, blur-then-submit validation).

### New field patterns introduced in Phase 2

| Pattern | Specification |
|---------|---------------|
| Hex / DevEUI input | `font-mono` input. Auto-strip whitespace, `-`, `:` on blur. Convert to lowercase on blur. Validation message: "Enter a {N}-character hex value." |
| Latitude / Longitude pair | Two number inputs side-by-side (`grid grid-cols-2 gap-4`). Range validation: lat ∈ [−90, 90], lng ∈ [−180, 180]. Helper under the pair: "Paste from Google Maps — example: `13.7563, 100.5018`." `Pick on map` ghost button rendered to the right with disabled tooltip "Available in v5." |

## Status Encoding Pattern (Phase 2 canonical)

The status-row component shipped in Phase 1 (Test Connection) is reused. Phase 2 introduces these canonical row shapes:

```
●  Healthy        Last uplink 3 min ago        ← --success dot, normal text, mono detail
●  Late uplink    Last uplink 47 min ago       ← --warning dot, normal text, mono detail
●  Offline        No uplink in 6 hours         ← --destructive dot, normal text, mono detail
○  Decommissioned Closed 2026-04-29            ← --muted-foreground hollow dot
●  Flagged        4 in last 24h • decode_fail  ← --warning dot, mono detail with bullet
```

- Dot is 8px filled `<Circle>` for active states, hollow `<Circle>` (stroke-only) for archived/decommissioned.
- Label is `text-sm font-normal`.
- Detail text is `text-sm font-mono text-muted-foreground` for technical content (uplink ages, counts), `text-sm text-muted-foreground` for prose.
