## Spacing Scale

Standard 8-point scale. All Phase 7 surfaces use these tokens only.

| Token | Value | Usage                                               |
|-------|-------|-----------------------------------------------------|
| xs    | 4px   | Icon gaps, chip row gaps, inline badge padding      |
| sm    | 8px   | Button internal padding, form field gaps            |
| md    | 16px  | Card padding, dialog section spacing, default gap   |
| lg    | 24px  | Between card sections, between primary layout areas |
| xl    | 32px  | Page-level padding, dialog max-width margins        |
| 2xl   | 48px  | Major section breaks in split panels                |
| 3xl   | 64px  | Not used in Phase 7 surfaces                        |

Exceptions:
- Codec test-runner split panel divider: 0px gap (flush border, no gap token) between left and right halves.
- Touch targets for mobile: minimum 44px height on all interactive rows and buttons (WCAG 2.5.5).
- DataTable row height: 48px minimum on mobile (touch-friendly).

## Surface Specifications

### Surface 1: Vendor Catalog Tab (Settings → Vendor Catalog)

Source: D-23, D-24, D-25, D-40, Phase 6 D-29 settings-table pattern.

**Route:** `/settings/vendor-catalog` (Settings tab strip, new tab)

**Tab label:** "Vendor Catalog" when no updates available; "Vendor Catalog (N)" when N > 0 entries have `update-available` status. The "(N)" count uses the same label typography as the tab text — no separate badge pill.

**Layout:**
- Full-width Card with CardHeader and CardContent, matching Phase 6 settings-table convention.
- CardHeader: title "Vendor Catalog" (heading 20px semibold), right-aligned help text "Manage device vendor profiles" (body 14px muted).
- CardContent: chip filter row (top) + DataTable (below).

**Chip filter row:**
- `gap-2 flex flex-wrap py-2` — capability chips: All | Water | Electricity | Multi-utility
- Each chip: shadcn Badge variant outline (inactive) / Badge variant secondary (active). Click to filter.
- Mobile: chip row scrolls horizontally (`overflow-x-auto flex flex-nowrap`) on 375px viewport.

**DataTable columns (D-23):**

| Column       | Width (desktop) | Width (mobile) | Notes                                                   |
|--------------|-----------------|----------------|---------------------------------------------------------|
| Vendor       | 160px           | shown          | Text, sortable                                          |
| Family       | 160px           | hidden (≤768px)| Text, sortable                                          |
| Capability   | 120px           | shown          | Badge chips (Water, Electricity) — not text            |
| Version      | 80px            | hidden (≤768px)| Semver text, sortable                                   |
| Installed    | 80px            | shown          | Checkmark icon if installed, dash if not               |
| Devices using| 100px           | shown          | Number; click navigates to `/devices?profile_id={id}`  |
| Status       | 160px           | shown          | Badge chip (not-installed / installed / update-available + version label) + "Update" button if update-available |

Mobile collapse rule: at viewport ≤ 768px, hide Family and Version columns. The Status column shows a compact badge only (no version text in badge). DataTable uses shadcn sheet (drawer) for row detail on mobile tap.

**"Update" button:**
- Appears inline in Status cell only when status = `update-available`.
- Button variant `outline` size `sm`. Label: "Update to v{X.Y.Z}".
- Click opens Update Diff Modal (Surface 3).

**Sorting:** Click column header to sort ascending; click again descending. Sortable: Vendor, Family, Version, Status. Default sort: Status descending (update-available rows first), then Vendor ascending.

**Empty state:**
- When catalog is empty (no profiles installed): centered text inside card — heading "No vendor profiles" (heading 20px), body "Import a profile from the vendor catalog to get started." (body 14px muted), Button primary "Browse catalog" that triggers the Import from Catalog flow inside Device Profiles.
- When chip filter returns no results: body text only "No profiles match the selected capability filter." No button.

**Loading state:** Three skeleton rows (Skeleton component) under the chip filter row.

**Accessibility:**
- DataTable has `role="grid"` with `aria-label="Vendor profiles"`.
- "Update" button has `aria-label="Update {vendor} {family} to version {X.Y.Z}"`.
- "Devices using" link has `aria-label="View {N} devices using {vendor} {family}"`.

### Surface 2: Import from Catalog Dialog

Source: D-03, D-04.

**Trigger:** "Add profile" button on Device Profiles list opens this dialog (or equivalent entry point from Vendor Catalog tab "Browse catalog" button).

**Component:** shadcn Dialog (max-width 560px on desktop, full-screen on mobile ≤768px).

**Step 1 — Start state selection:**
- Dialog title: "Add Device Profile" (heading 20px semibold).
- Two vertically-stacked radio cards (RadioGroup):
  - Card A: "Start blank" — radio + label "Create a new profile from scratch" (body 14px).
  - Card B: "Import from catalog" — radio + label "Start with a pre-configured vendor profile" (body 14px).
- Selecting "Import from catalog" reveals the catalog table picker inline (same dialog, no step navigation UI) — the two radio cards shrink to compact row height and the picker expands below.
- "Continue" button (primary) advances to Step 2. Disabled until a selection is made.

**Step 2 — Catalog picker (when "Import from catalog" is selected):**
- Compact searchable list using shadcn Command component embedded inside the dialog (not a popover — embedded inline, max-height 260px, scroll-area).
- List item row: Vendor + Family (bold) | Capability chips | Version (muted). 48px row height.
- On selection: selected item highlighted with primary color border, checkmark icon.
- "Continue" button enabled after selection.

**Step 3 — Review form (prefilled from catalog):**
- Dialog title changes to "Review Profile: {vendor} {family}" (heading 20px).
- Form fields (React Hook Form + zod) prefilled from catalog entry:
  - Profile name (Input, required, max 80 chars) — pre-populated as "{vendor} {family}".
  - Capability (read-only Badge chips from catalog).
  - Codec (Textarea, pre-populated from catalog codec JS, editable — per D-04 editability).
  - Expected uplink interval (Input type=number, pre-populated from catalog, labeled "Expected uplink interval (seconds)").
- All fields are editable — catalog is a seed, not a lock (D-04).
- Footer: "Back" button (outline) | "Add Profile" button (primary).

**Error states:**
- Profile name already exists: inline field error "A profile with this name already exists."
- Form submit network error: toast (sonner) "Failed to add profile. Try again."

**Success:** Dialog closes; sonner toast "Profile added" (body 14px). Device profiles list invalidates.

**Accessibility:**
- Dialog has `aria-labelledby` pointing to title id.
- Focus moves to first interactive element on open (radio group).
- Escape closes dialog, focus returns to trigger button.

### Surface 3: Update Diff Modal

Source: D-24, D-34, D-36.

**Trigger:** "Update to v{X.Y.Z}" button in Vendor Catalog tab row.

**Component:** shadcn Dialog (max-width 640px on desktop, full-screen on mobile ≤768px).

**Header:**
- Dialog title: "Update {vendor} {family}" (heading 20px semibold).
- Subtitle: "v{current} → v{catalog}" (body 14px muted).
- Description: "Review changes field by field. Fields you've edited are flagged — your edits are preserved by default." (body 14px).

**Diff table:**
Layout is a 5-column table inside a ScrollArea (max-height 400px):

| Column | Width | Content |
|--------|-------|---------|
| Field  | 20%   | Field name (label 12px) |
| Current value | 28% | Value from operator's device_profile row (body 14px, `text-muted-foreground`) |
| Catalog value | 28% | Value from new catalog version (body 14px, `text-foreground`) |
| Toggle | 16%  | "Use mine" / "Use catalog" — ToggleGroup with two options |
| Flag   | 8%   | "Edited" Badge (outline variant, warning color) if `customer_edited=true` for this field |

Toggle default state logic (D-34):
- If the field's value differs AND `customer_edited = false`: default toggle = "Use catalog".
- If the field's value differs AND `customer_edited = true`: default toggle = "Use mine".
- If the field's value is unchanged: row is not shown in the diff table (unchanged fields are hidden).

Toggle component: ToggleGroup with two ToggleGroupItem ("Use mine" / "Use catalog"). Selected state uses primary color fill. Size `sm`.

**Unchanged fields summary:** Below the diff table, a collapsed section "N fields unchanged (not shown)" — body 14px muted, no expand needed.

**Syncing badge (D-36):** After confirmation, while seed routine re-syncs codec to ChirpStack, the Vendor Catalog table row shows a Badge with `--warning` background labeled "Syncing to ChirpStack…" until `codec_js_synced_at` is populated. No second confirmation dialog.

**Footer:**
- "Cancel" button (ghost variant).
- "Apply Update" button (primary). Disabled while toggle form is loading. Tooltip on hover: "This will update {N} changed fields."

**Error state:** Toast "Update failed. {error message}. Try again."
**Success:** Dialog closes; toast "Profile updated to v{X.Y.Z}"; catalog table row status changes to "installed".

**Accessibility:**
- ToggleGroup items have `aria-label="Use my value for {field name}"` and `aria-label="Use catalog value for {field name}"`.
- "Edited" flag badge has `aria-label="You have edited this field"`.
- Focus trap inside dialog.

### Surface 4: Codec Test-Runner Panel

Source: D-05, D-06, D-07, D-08, D-26, D-27, D-28.

**Placement:** Inside the device-profile editor dialog (or page), as a collapsible panel below the Codec JS textarea. Uses shadcn Tabs or an Accordion-style expand. The panel label is "Test Codec" with a chevron icon. Collapsed by default; click to expand.

**Expanded layout (desktop — two-column split):**
```
┌─────────────────────────────────────────────────────┐
│ Test Codec                                  [Collapse]│
├─────────────────────────┬───────────────────────────┤
│ Input                   │ Output                     │
│                         │                            │
│ fPort [Input number]    │ ← Decoded JSON (left)      │
│                         │   OR                       │
│ Hex payload [Textarea]  │ → Canonical Mapping (right)│
│                         │   (tabs or vertical split) │
│ [Test] button           │                            │
└─────────────────────────┴───────────────────────────┘
```

**Input pane (left, desktop 50% / mobile 100% stacked first):**
- Section heading: "Input" (label 12px semibold uppercase muted).
- fPort field: Label "fPort (optional)" + Input type=number, width=80px, min=0, max=255. Placeholder "e.g. 1".
- Hex payload field: Label "Payload (hex bytes)" + Textarea, `font-mono` 13px, rows=4, placeholder "e.g. 6F 01 23 45 AB CD". Accepts space-separated or continuous hex.
- "Run Test" button: primary variant, full-width on mobile, width=auto on desktop. Icon: Play (lucide). Disabled when textarea is empty.
- Below button: small muted text "Results are not saved. Clear the form to reset." (body 12px muted).

**Output pane (right, desktop 50% / mobile 100% stacked below input):**
- Section heading: "Output" (label 12px semibold uppercase muted).
- Uses shadcn Tabs with two tabs: "Decoded JSON" | "Canonical Mapping".
- Tab "Decoded JSON":
  - Renders the decoded JSON tree using the existing `JsonTree` component (`web/src/components/metering-point/JsonTree.tsx` — Phase 4 component, reuse directly).
  - Copy button (icon-only, lucide Copy, tooltip "Copy as JSON") in top-right of tab panel.
- Tab "Canonical Mapping":
  - Renders the canonical shape `{mp_id, cumulative_value, battery_pct, rssi, ...}` as a JsonTree.
  - Copy button same as above.
- Loading state: Skeleton (3 lines) while awaiting response.
- Empty state (before first test): centered muted text "Run a test to see output here." (body 14px muted).

**Error panel (replaces output pane on codec failure, D-28):**
- Background: `bg-destructive/10 border border-destructive/30 rounded-md p-4`.
- Layout:
  - Row 1: Error type label (label 12px semibold, `text-destructive`) + error message (body 14px).
  - Row 2: "at line {N}, column {M}" (body 14px, `font-mono`).
  - Row 3 (if stack available): Collapsible "Stack trace" with Accordion; stack text in Textarea-like box with `font-mono` 13px, `select-all` on click, read-only.
  - Copy stack trace button (outline variant, size sm): "Copy Stack Trace".
- The right-tab output panel grays out (`opacity-40`) when error panel is active.

**Mobile layout (≤768px):** Input pane full width, Run Test button full width, Output pane full width below. Total scrollable column.

**Accessibility:**
- "Run Test" button has `aria-busy="true"` while loading.
- Error panel has `role="alert"` so screen readers announce it.
- Tabs follow ARIA tabs pattern (existing shadcn Tabs component handles this).

### Surface 5: Compare View

Source: D-16, D-37, D-38.

**Route:** `/compare` — new top-level route.
**Nav entry:** Sidebar navigation item "Compare" (lucide GitCompare icon), visible to all authenticated users.

**Page layout:**
```
┌─────────────────────────────────────────────────────┐
│ Compare                                             │
│ [Compare entities] [Compare time ranges]  ← RadioGroup│
├─────────────────────────────────────────────────────┤
│ Entity A [searchable dropdown]  ⇄  Entity B [searchable dropdown] │
│ Time range: [preset buttons] [custom picker]        │
│ ─────────────────────────────────────────────────── │
│ [2-series overlay chart]                            │
│ ─────────────────────────────────────────────────── │
│ [2-row data table with delta column]                │
└─────────────────────────────────────────────────────┘
```

**Mode toggle (top, D-38):**
- RadioGroup displayed as two Button-like pills: "Compare entities" | "Compare time ranges".
- "Compare entities" mode (default): two entity dropdowns + single time-range picker.
- "Compare time ranges" mode: single entity dropdown + two time-range pickers (A range / B range).
- Mode toggle is `sticky top-0` on desktop, above the fold on mobile.

**Entity dropdowns (D-37):**
- Component: shadcn Popover + Command (search-inside-popover pattern from MeterCombobox.tsx).
- Placeholder: "Select entity A" / "Select entity B".
- Each dropdown shows sites and metering points, but not mixed — a type selector (segmented control or two tabs inside the Command: "Sites" | "Metering Points") constrains both dropdowns to the same type.
- Swap button (⇄): icon-only Button ghost between the two dropdowns, `aria-label="Swap entity A and B"`.
- Width: `w-64` on desktop, `w-full` on mobile.

**Time-range picker:**
- Reuse existing `CustomDateRangePicker` from `ReportConfigPanel.tsx` plus range preset buttons (This month, Last month, This year, Last year).
- In "Compare time ranges" mode: two labeled pickers — "Range A" and "Range B" — side by side on desktop, stacked on mobile.

**Chart area:**
- Component: shadcn chart (Recharts wrapper, existing `chart.tsx`).
- Two line series overlaid: Entity A (primary color: `--primary`) + Entity B (`--info` oklch(0.55 0.15 240)).
- Legend: two colored dots + entity names. Positioned top-right on desktop, below chart on mobile.
- Y-axis: consumption unit (m³ or kWh, from entity capability).
- X-axis: time.
- Loading state: Skeleton rectangle (h-48).
- Empty state (no entity selected): centered muted text in chart area "Select two entities to compare." (body 14px muted).
- No data: centered muted text "No data for this range." (body 14px muted).

**Data table (below chart):**
- 2 rows (one per entity) + header row + delta row.
- Columns: Entity | Total consumption | Average per period | Peak | Delta vs other.
- Delta column shows +/- value with arrow icon. Positive delta: `text-success`. Negative delta: `text-destructive`. Zero: `text-muted-foreground`.
- Table uses `<Table>` (existing shadcn table.tsx). Width 100%.

**Mobile layout (≤768px):**
- Mode toggle: full-width two-pill radio.
- Entity dropdowns: stacked vertically (A above B, swap button between).
- Time range picker: full-width.
- Chart: full-width, h-48.
- Data table: card-stacked rows instead of table columns (each entity as a Card with key-value rows).

**Empty state (no route data):**
- Full-page centered: heading "Compare two entities" (heading 20px), body "Choose entities and a time range to see side-by-side consumption data." (body 14px muted).

**Accessibility:**
- Swap button: `aria-label="Swap entities A and B"`.
- Chart: `aria-label="Comparison chart for {entity A name} vs {entity B name}"` and `role="img"`.
- Mode radio group: `aria-label="Comparison mode"`.

### Surface 8: Settings Catalog "Update Available" Tab Badge

Source: D-02, D-40.

**Location:** Settings page tab strip only. No app-wide banner, no sidebar nav badge (D-40 operator-pull model).

**Implementation:** The Settings tab strip renders "Vendor Catalog" or "Vendor Catalog (N)" where N is the count of profiles with `status = update-available`. The count is fetched on Settings page mount.

- 0 updates: "Vendor Catalog"

## Cross-Surface Notes

### Auto-surfaced raw JSONB fields (no new UI work required)

Phase 4 `AdvancedTab.tsx` uses `jsonb_each` to auto-surface all `measurement.raw` fields. Itron+KINMY's `meter_id`, `reverse_flow_m3`, `meter_date`, `meter_time`, and `battery_v` will appear in the Advanced tab of any Metering Point detail page automatically after Phase 7 ships. This is a free benefit — no Phase 7 UI work needed for raw field display.

### Backtest button for alert rules (D-10, D-35)

The "Test against last 30 days" button and its result panel (count + 30-bar sparkline) are placed inside the existing AddRuleDialog and the rule-library row in `alerts.tsx`. This is an extension of Phase 6 UI surfaces, not a new surface. The executor should:
- Add "Test against last 30 days" Button (outline, size sm) to `AddRuleDialog.tsx` below the rule configuration fields.
- Render result below: "{N} fires in the last 30 days" + a compact BarChart (shadcn chart, 30 bars, height 48px) showing fires-per-day.
- Loading state: Skeleton (h-12).
- Zero fires: "0 fires in the last 30 days — this rule would not have fired. Defaults may be well-tuned for this meter." (body 14px muted).

### anomaly_compatibility rule hiding (D-42)

In `AddRuleDialog.tsx`, the available rule types must be filtered by the metering point's bound profile `anomaly_compatibility`:
- `full`: all three rules visible (anomaly_p95, anomaly_iqr, anomaly_quiet_hour).
- `limited`: anomaly_p95 and anomaly_iqr visible; anomaly_quiet_hour hidden entirely (not disabled, hidden).
- `unsupported`: all three rules hidden; a muted info banner shows "Anomaly detection is not available for this device type." (Alert component, variant default/info).

### "Syncing to ChirpStack…" badge lifecycle

After a catalog Update is applied (Surface 3), the Vendor Catalog table row Status cell shows an additional Badge (warning color, "Syncing to ChirpStack…") alongside the "installed" status. This badge is removed when the profile row's `codec_js_synced_at` is set. The frontend should poll `/api/catalog` every 5 seconds for rows where sync is pending, or listen via SSE if the backend emits a profile_synced event.
